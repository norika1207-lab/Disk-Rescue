# 08 多重異地備份（消除單點風險）

救援成功後，若某批資料只存在一顆碟上（唯一副本），那顆碟一旦故障就全沒了。這章講怎麼把「唯一副本」安全地做成多份、分散到不同機器，每一步都驗證。

## 核心原則：先多份、驗證過，才動原件

順序不能錯。若你打算格式化或挪用存著唯一副本的那顆碟，鐵律是：

1. 複製到第二個位置 → 驗證完整
2. 複製到第三個位置（不同機器 = 真異地）→ 驗證完整
3. 三份都確認齊全，才動原件

任何一步的「複製完成」都不等於「複製正確」，必須驗證（見下）。

## 第一份：複製到本地另一顆碟

```
rsync -rlt --partial --no-perms --no-owner --no-group 來源/ 目的/
```

跨檔案系統（如 APFS→exFAT）不要硬帶權限。注意：**即使加了 `--no-perms`，macOS 寫到 exFAT 仍可能替每個檔生成 AppleDouble（`._`）伴生檔**（實測一次複製 3.2 萬檔生出 3.5 萬個 `._`）。這不影響正本，但要在複製後清掉（見 [05](05-three-disk-reorg.md) 的 dot_clean）。

## 第二份：跨機器複製（真異地）

透過 SSH + rsync 傳到另一台機器。目的地若是 Linux 原生檔案系統（ext4），就不會有 `._` 問題。

```
rsync -rlt --partial -e "ssh -o ConnectTimeout=20" \
      來源/ 使用者@主機:/目的路徑/
```

`--partial` 讓中途斷線可續傳。跨網路（如 VPN）傳輸速率會遠低於本機直連，大批資料要有耐心，讓它背景跑。

### 跳板：目標機在不同內網

若目標設備（例如 NAS）跟你當前機器不在同一內網（`192.168.1.x` vs `172.16.0.x`），直連不到。解法是找一台「跟目標同內網、你又連得到」的機器當跳板：

```
# 先確認跳板能搆到目標
ssh 跳板機 "ping -c 2 目標內網IP"
# 再透過跳板 rsync（ProxyJump）
rsync -rlt -e "ssh -J 跳板機" 來源/ 使用者@目標:/路徑/
```

判斷哪台能當跳板：`ssh 候選機 "ifconfig | grep 'inet '"` 看它的內網網段是否涵蓋目標。

## 每份都要驗證（四項）

複製完，對每個目的地做四項檢查，全過才算數：

```bash
# 1. rsync 有無錯誤
grep -iE "error|failed|No space|broken pipe" rsync.log

# 2. 檔數比對（排除 ._ 與傳輸暫存檔）
find 目的 -type f ! -name '._*' ! -name '.*.??????' | wc -l   # 對比來源

# 3. 總 byte 數比對（權威：逐檔加總，不看 du 的區塊估算）
find 目的 -type f ! -name '._*' -printf '%s\n' | awk '{s+=$1} END{print s}'
#   Linux 用 -printf '%s'；macOS 用 stat -f%z

# 4. 殘留暫存檔（.xxx.隨機碼 = 沒傳完）
find 目的 -name '.*.??????' -type f | wc -l   # 應為 0
```

byte 數要用「逐檔加總」，不要用 `du`（du 算的是區塊佔用，跨不同配置單元的檔案系統會對不上，造成假不符）。

## 監控長時間傳輸：別用檔數判斷卡沒卡

跨網路傳大批資料常含幾十 GB 的單一大檔。這種時候「已完成檔數」會長時間不動（還在傳同一個大檔），用檔數當「是否卡住」的指標會誤報。

正確做法：看**目的端實際容量**有沒有增長，或用 `lsof` 看傳輸暫存檔有沒有變大：

```bash
# 目的端（Linux）看暫存檔 20 秒有沒有長
ssh 目標 "find /路徑 -name '.*.??????' -exec stat -c%s {} \;"   # 隔 20 秒再測一次
```

暫存檔在長 = 正常在傳；連續數十分鐘容量零增長，才是真卡。判「卡住」用「一段時間毫無進展」，不用「單一計數不動」。

## 完成後

三份齊全、各自驗證通過，才可以對原件做不可逆操作（格式化 / 挪用）。若原件那顆碟還有用途，就保持原樣別動 —— 多一份副本永遠不虧。
