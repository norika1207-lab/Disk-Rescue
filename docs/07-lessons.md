# 07 工程教訓

## 認碟鐵則

- **永遠用卷標認碟，絕不 hardcode 磁碟編號。** 外接碟拔插、重開機後磁碟編號會重編（disk2 可能變成別顆）。一條 hardcoded `select disk 2` 的格式化指令，就是本專案第二起災難的根因。
- 任何格式化 / 覆寫 / 刪除前，當下重新 `diskutil list external physical` 對齊，並用容量 + 卷標 + 讀 magic 三重確認目標。
- 兩顆同型號同容量的碟，用「內容特徵檔」分辨（例如某個獨有的大檔），不靠編號。

## 不可逆操作的順序

格式化 / 刪除來源前，鐵律三步：
1. 資料已在另一顆「可讀」的碟上（不是「傳完了」，是「讀得開」）。
2. 逐檔 byte 或 checksum 驗證過完整。
3. 才動來源。

唯一副本在動手前必須先變成至少兩份。

## 觀測先於推論，別把「慢」當「壞」

- 讀得慢、偶爾卡（U 狀態）≠ 碟壞。用過嚴的 timeout（如 4 秒探針）會把好區誤判成壞區。先觀測實際吞吐（ddrescue 速率、used space 變化）再下結論。
- 大檔搬移/解包時容量在漲、進程在動，就是正常，別因為「檔數不動」或「進度數字沒跳」就判卡住 —— 先 `lsof` 看它在寫哪個檔。

## 進度監控的正確做法

- 別相信單一粗指標（df 有時給抽風假數字）。用 `diskutil info` used space + `lsof` 寫入路徑 + 進程狀態三者交叉。
- 監控要涵蓋失敗路徑：只看「成功標記」的監控，遇到進程崩潰會靜默，看起來跟「還在跑」一樣。判斷「卡住」用「一段時間毫無進展」而非單次讀取。

## 報告紀律

- 沒親自驗證的不當事實講。指令 exit 0 ≠ 內容正確；ls 抽風的輸出 ≠ 真實狀態 —— 關鍵結論用 `test` / `find` 實證，貼得出數據才算數。
- 講錯立刻更正，別讓一個基於抽風輸出的「已完成」蒙混過去。

## exFAT 特性備忘

- 不支援 Unix 權限、symlink、xattr；配置單元大（常見 256KB），海量小檔嚴重膨脹。
- macOS 會在上面生 `._` AppleDouble 伴生檔。
- 沒正常卸載就拔，macOS 下次掛回會跑檔案系統檢查（可能數十分鐘），別中斷別重開機，跑完自動掛回、資料無損。拔碟前一定 `diskutil unmount`。
