# 05 多碟重組

救回資料後，常要把幾顆碟重新分工：一顆當日常工作碟、一顆當備份倉庫、一顆放獨立副本。過程中會遇到格式化、大量搬移、解包、清理。

## 格式化 vs 刪除：清海量小檔一定用格式化

一顆碟若累積了數百萬個小檔（爛掉的 Trash、中繼產物），想「用刪的」清乾淨，在 exFAT 上會慢到不可行（實測刪不完、耗數週）。

正解：把要保留的資料先確認在別處有可讀副本並驗證過，然後**格式化**整顆碟（幾秒清空），再把乾淨資料搬回。刪海量小檔用格式化，不要一個一個刪。

## 搬移用 rsync，可續傳

```
rsync -rt --partial --no-perms --no-owner --no-group 來源/ 目的/
```

`--partial` 讓斷線後重跑自動跳過已傳、只補未傳，不從頭來。跨檔案系統（APFS→exFAT）不要硬帶權限/擁有者。

macOS 內建的是 openrsync，不支援 GNU rsync 的 `--info=progress2` 等新參數，別誤用。進度改看 `diskutil info` 的 used space 變化。

## 從 tar 解回檔案樹

要讓資料能直接開來用（不是一堆打包檔），就得解開。但解到 exFAT 會遇到 AppleDouble 問題（見下）。解大 tar（內含 Android prebuilts、git packfile 這種幾十萬小檔）會很慢，屬正常，不是卡住 —— 判斷卡沒卡看 used space 有沒有持續增加，別只看進程狀態。

## AppleDouble（`._` 檔）：exFAT 上的隱形垃圾

macOS 在非原生檔案系統（exFAT）上，會為每個帶 extended attributes 的檔案額外產生一個 `._開頭` 的伴生檔（AppleDouble 格式，開頭 magic `00 05 16 07`），存 xattr / resource fork。

- 用 `tar -x` 把「本身就含 `._` 條目」的 tar 解到 exFAT，會把這些 `._` 全還原出來 → 檔案數暴增一倍。實戰中一次解包產生了 94 萬個 `._`。
- 每個 `._` 只有 4KB，卻各吃一個 256KB 配置單元 → 憑空多佔數百 GB。

清除：用系統內建 `dot_clean`，它把 `._` 的 xattr 併回正本再刪，批次處理整顆碟，比 `find -delete` 逐檔快得多。

```
dot_clean -m /Volumes/外接碟     # -m: 併回後刪除所有 ._ 檔
```

實測：94 萬個 `._` 用 dot_clean 約每秒 100 個、兩三小時清完（同一批用 Finder 逐刪要數週）。跑完可能殘留極少數（深層/特殊字元），再補一次即可。

## 驗證檔數時要排除 `._`

比對 tar 內項目數 vs 磁碟解出項目數時，磁碟端會多出 `._`（一比一），造成「兩倍」假象。比對時兩邊都要排除 `._`（`grep -v '/\._'`），否則誤判。
